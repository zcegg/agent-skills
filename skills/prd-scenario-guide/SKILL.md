# 第二轮 · 场景交互导读

交付一份能在本地直接打开的单页 HTML。读者先能说出“同一个人为什么走到不同页面”，点进场景后能演示“我看到什么，能做什么，做了会怎样”。第一轮导读如已有，可辅助定位范围，直接从 PRD 开始也可以。

## 先定场景，再画页面

- 沿用用户指定的端、入口和业务范围。提取会改变可见页面、可做动作或操作结果的条件。仅在确实改变体验时，才按角色、时间、权限、首次或再次进入拆场景。同状态下查效果与申请退出可以是两个目标；避免枚举所有条件的组合。
- 以“谁，在什么情况下，想做什么”为场景标题。每个场景先写一行可观察结果。按真实生命周期组织阶段，同一阶段的不同选择并列；没有先后关系时按用户目标分组。期数和状态机只在有依据时使用。
- 读取对应 PRD 段落和现有代码，沿真实入口追到页面、组件、路由和响应消费位置。无 UI 稿时，用已有产品的页面骨架和交互习惯搭可操作示意。记录仓库、版本与相对路径。若代码已含本次实现且任务要求模拟开发前，取功能开发前基线。代码不可读时注明缺口，只为有依据的部分落图。
- PRD 说明业务要求，代码说明已存在的能力。已核实的接口和字段给出消费位置；缺合同时只写“前端需要知道什么”，点明谁确认。相似组件、截图、示例数据和后来的实现均不能单独证明新规则。原文冲突时两种口径就地可见，问题交给能决定它的人。

## 默认桌面样式 · 石墨分镜

以实际 HTML 截图为准：[场景总览](references/desktop-reading.png)、[展开状态图的场景详情](references/graphite-detail.png)。两轮共用固定左栏、石墨底色、浅色正文和薄荷绿选中路径。把 [assets/guide.css](assets/guide.css) 内联至文件，使用 `body.guide > main.guide__page`、`header.guide__header`、`nav.guide__nav` 和 `aria-current="page"`。页面名称与分支数量来自当前 PRD。两份导读均存在时，左栏用相对路径互跳；单独交付只提供可用入口。

1. **先选场景。** 首屏展示场景全貌。按真实阶段或目标分组，组内把并列问题排在同一层。用 `guide-map` 和 `guide-case` 展示可以点入的问题、一句可观察结果和角色／页面。保留键盘入口、场景直链和返回原入口的焦点。
2. **再看分镜。** 场景内依次显示返回入口、场景问题、一句话结果、示意条件切换，再用 `guide-strip` 演示「进入页面 → 查看与操作 → 操作结果」。把连续步骤排成有序列表，给角色交接或时间跳转标明条件。同一判断的不同结果并列。把业务按钮与导读用的条件切换区分；失败分支贴近发起动作，影响去向的待确认项贴近结果，写明由谁确认。
3. **按需查判断。** 分镜下按「页面状态图 → 决策表 → PRD 与代码依据」排列，初始收起。每张图均可拖动平移、放大、缩小、显示比例和适应窗口；键盘可选节点、平移和操作缩放按钮。短按选择分支，从节点起拖只平移。选中的节点和对应连线同时高亮。决策表对照条件、前端判断、用户所见与去向、口径及待确认方。
4. **图表共享一次选择。** 用同一分支标识连接条件按钮、分镜结果、图节点／路径及表行。点决策表条件会展开状态图、把对应节点带回视野并聚焦。点图节点或切换条件后，表中对应行同步选中。直接内联 [assets/state-map.js](assets/state-map.js)，按[接入约定](references/state-map.md)装配业务数据与回调。图形与脚本离线可运行；使用 Mermaid 时内嵌运行时或预渲染。

## 交付前用桌面浏览器走读

在 1280 × 720 检查总览可读性，再用宽桌面对照两张基准。逐个场景验证进入与返回、条件切换、页面动作、异常分支及键盘焦点。对每张状态图实际放大，从节点按住拖动，确认画面移动且选中项稳定；再缩小、适应窗口，核对所有节点可见。把画布移开后点表行，应定位到对应路径；点另一节点，应更新结果及表行。最后用本地 HTML 打开验证，交付可留存文件，区分导读演示与真实接口联调。默认按桌面交付，移动端适配和验收用例按用户要求另行展开。
